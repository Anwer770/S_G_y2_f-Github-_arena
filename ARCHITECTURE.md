# خريطة المعمارية والطبقات المستهدفة (Architecture Map)

> **دستور المشروع:** التطبيق يتبع نمط **Offline-First** أحادي المصدر (Single Source of Truth)، حيث تكون كافة العمليات التجارية مخزنة محلياً في **IndexedDB** ومغلفة بطبقة مستودعات وخدمات، ومجهزة للتوسيع السحابي المستقبلي (Cloud / Firebase / Supabase) دون كسر واجهات الاستخدام.

---

## 2. الوضع الحالي والانحرافات المرصودة (As-Is vs. Target)

### 2.1 المساران المتوازيان للتخزين (Dual Data Paths)
* **الوضع القائم:**
  * **المسار الأول (الحديث):** Component → Service → Repository → `IndexedDBAdapter`.
  * **المسار الثاني (الموروث):** Component / `App.tsx` → `utils/storage.ts` (`load*` / `save*`) → `dbStorage`.
* **الخطر والانحراف:** وجود مسارين لنفس الكيان قد يسبب ازدواجية في منطق التعديل وتكرار قراءة الذاكرة.
* **الحل المعماري التدريجي (المرحلة 3):** توحيد كافة استدعاءات `App.tsx` والوحدات لتمر عبر طبقة الخدمات والمستودعات كواجهة موحدة (Facade) مع الحفاظ الكامل على توافق العقود والتسميات.

### 2.2 بوابة الجاهزية عند الإقلاع البارد (Cold-Start Readiness Gate)
* تم تطبيق بوابة التحقق `indexedDBStorage.initPromise` لمنع أي قراءة أو كتابة قبل اكتمال تحميل IndexedDB، مما أغلق خطر فقدان البيانات (R1) تماماً.

### 2.3 طابور المزامنة الصادرة (`suite_sync_outbox_v1`)
* تم ضبط سقف أقصى 2000 سجل مع استراتيجية FIFO لتفريغ السجلات القديمة تلقائياً مع الحفاظ على سجل التدقيق ومنع تضخم التخزين.

## 3. طبقة التجريد السحابي والذكاء الاصطناعي (Cloud & AI Abstraction)

### 3.1 الاستعداد لـ Firebase / Supabase / Cloud
* لا يتم الاتصال المباشر بأي واجهة سحابية من داخل مكونات الأعمال (Business Components).
* تم تصميم طبقة المستودعات لترث من `BaseRepository` وتدعم واجهة `ISyncEngine` مستقبلاً:
  * تسجيل كل حدث `INSERT / UPDATE / DELETE` في `sync_outbox`.
  * إمكانية توصيل `FirebaseProvider` أو `SupabaseProvider` في مرحلة لاحقة دون إعادة كتابة أي شاشة من شاشات النظام.

### 3.2 تجريد مزودي الذكاء الاصطناعي (AI Provider)
* استخدام واجهة `AIProvider` لعزل نموذج الذكاء الاصطناعي (Gemini أو غيره) عن واجهات المستخدم ومحررات الملاحظات، مما يمنح مرونة كاملة في التبديل بين النماذج أو العمل دون اتصال (Local AI).

## 4. خطة التخلص من التكرار والمخاطر المتبقية

1. **توحيد دوال التاريخ المشتركة (`todayStr`, `today`)**: استخراجها في موديول موحد `src/utils/date.ts` مع اختبار تطابق المخرجات تماماً.
2. **عزل مكتبة `xlsx`**: وضع واجهة استيراد وتصدير موحدة للتحقق من سلامة الملفات والتصدي لأي ثغرة محتملة في معالجة الجداول.
3. **تحسين أداء التمرير (Props Drilling)**: الاستفادة من التخزين المؤقت وحسابات `useMemo` للحد من إعادة التصيير غير الضرورية في شجرة المكونات.
