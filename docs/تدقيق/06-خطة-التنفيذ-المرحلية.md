# 06 — خطة التنفيذ المرحلية (Incremental Refactoring Plan)

> التطبيق يبقى **قابلاً للتشغيل بعد كل خطوة** (§12). لا تُدمج مرحلتان في Commit واحد (§66).
> كل مرحلة تُغلق بـ: انحدار آلي (`tools/regression`) + تحقق يدوي + تحديث `Changed/Added/…` (§67).

## ترتيب مراحل التنفيذ
| المرحلة | النطاق | مخرجات ملموسة | البوابة (Gate) |
|---|---|---|---|
| **Phase 2 — Safety** (الحالية) | شبكة أمان قبل أي تعديل | أداة انحدار آلية + خط أساس محفوظ + استراتيجية نسخ/تراجع | الأداة تعمل وتُنتج تقرير «قبل» |
| **Phase 3 — Refactor (بيانات أولاً)** | R1 ثم R2 ثم توحيد مسار البيانات | حماية من فقدان البيانات + إيقاف تضخّم Outbox | صفر تغيير في السلوك المرئي + تطابق العدّادات |
| **Phase 4 — UX/UI للشاشات الاستعراضية** | لوحة القيادة، الجداول، الفلاتر، البحث، الحالات الفارغة، الوضع الليلي، الجوال | واجهة أوضح بلا لمس المكونات الـ46 وظيفياً | بطاقة تحقّق لكل مكوّن محمي عُدّل بصرياً |
| **Phase 5 — Responsive** | 390px، جداول القوائم، أزرار اللمس | استخدام بيد واحدة | فحص على 3 مقاسات + RTL |
| **Phase 6 — Performance** | تقليل props، memo، lazy، تجزيء الحزمة | إقلاع أسرع ورسم أقل | قياس قبل/بعد موثّق |
| **Phase 7 — AI Layer (هيكل فقط)** | واجهة مزوّد + خدمة + Prompt Manager + تأكيد المستخدم قبل أي إجراء | طبقة جاهزة بلا تنفيذ حساس مباشر | لا تأثير على الوظائف الأساسية |
| **Phase 8 — QA/Security** | R3 (PIN)، R4 (xlsx)، تدقيق شامل + تقرير نهائي (§74) | إغلاق المخاطر الأمنية | كل بنود §73 خضراء |

## Phase 3 — تفصيل (تبدأ فقط بعد موافقة المستخدم)
### 3.1 حماية من فقدان البيانات (R1) — الأعلى أولوية
**التغيير المقترح (الأقل تدخلاً):**
```ts
// 1) IndexedDBAdapter: كشف جاهزية صريح
public ready(): Promise<void> { return this.initPromise ?? Promise.resolve(); }

// 2) main.tsx: عدم تركيب الواجهة قبل اكتمال التهيئة
await indexedDBStorage.ready();   // top-level await مدعوم في Vite
createRoot(document.getElementById('root')!).render(…);

// 3) منع الكتابة فوق بيانات لم تُقرأ بعد (شبكة أمان ثانية داخل dbStorage)
//    أي setItem لمفتاح لم تُكتمل قراءته بعد يُؤجَّل حتى ready()
```
**لماذا آمن:** لا يغيّر أي Data Contract، ولا أي مكوّن محمي، ولا حقل تخزين. أثره: تأخير تركيب الواجهة بمقدار زمن تحميل IndexedDB (مللي ثوانٍ).
**الاختبار المطلوب:** إقلاع بمجموعة > 500KB ⇒ تطابق العدّ (`Before Count = After Count`) + لا ظهور بيانات افتراضية.

### 3.2 Outbox (R2)
- الخيار الآمن: **تفريغ بعد النسخ الاحتياطي** أو تقييد الحجم مع الاحتفاظ بعدّاد، وعدم حذف أي سجل بيانات حقيقي.
- يجب قرار المستخدم: هل المزامنة بين الأجهزة هدف فعلي؟ (إن نعم: يُربط `SyncEngine` الموجود؛ إن لا: يُعطَّل التسجيل أو يُصغَّر إلى Audit Log).

### 3.3 توحيد مسار البيانات (R5)
- الهدف: مصدر واحد لكل Domain (`service`), مع إبقاء `utils/storage.ts` كطبقة توافق خلفي (لا حذف).
- الخطوات: تسجيل كل قارئ/كاتب (`03-عقود-البيانات`) → تحويل القراءة إلى الخدمة → تحويل الكتابة → إبقاء الـ API القديم كغلاف.

## قواعد التنفيذ الإلزامية (ملخّص عملي من البرومبت)
1. قبل أي تعديل: `ما الموجود؟ → لماذا التغيير؟ → من يعتمد عليه؟ → ما الذي قد ينكسر؟ → كيف نختبره؟` (§69).
2. أي مكوّن محمي: **Visual فقط** — ولو اضطررت لتعديل سلوكه، توقف وحلّل التبعيات أولاً (§7، §78).
3. أي Bug داخل مكوّن محمي: `Reproduce → Root Cause → أقل إصلاح → حفظ السلوك → انحدار` (§70).
4. الكود المكرر: لا يُدمج قبل إثبات تطابق Behavior/Inputs/Outputs/Side effects (§72).
5. لا ميزات عشوائية: كل ميزة جديدة قابلة للإزالة دون كسر النظام (§64).
6. Commits صغيرة ببادئات: `refactor:` `fix:` `ui:` `performance:` `architecture:` `test:` `ai:` `docs:` (§66).
7. بعد كل مرحلة: Change Log بصيغة `Changed / Added / Removed / Refactored / Protected / Fixed / Performance / Potential Risks` (§67).

## شبكة الأمان (Phase 2) — كيف تعمل
```
tools/regression/run.mjs
  ├── 1. إقلاع التطبيق فعلياً (jsdom) على الشيفرة الحالية
  ├── 2. تسجيل الدخول (مسارات: دخول سريع / PIN)
  ├── 3. زيارة كل التبويبات الـ14 والتقاط أخطاء الكونسول
  ├── 4. قراءة كل مفاتيح التخزين وعدّ السجلات  ← «Before Count»
  ├── 5. تنفيذ CRUD حقيقي (إضافة قيد مالي) والتحقق من الحفظ
  └── 6. كتابة docs/تدقيق/baseline.json ليقارن به أي تشغيل لاحق
```
**معيار النجاح:** نفس العدّادات، صفر أخطاء JS جديدة، نفس المسارات تعمل.

## خطة التراجع (Rollback)
- كل مرحلة في فرع/Commit مستقل ⇒ `git revert <sha>` يُعيد الحالة السابقة فوراً.
- البيانات: `BackupService.createBackup()` قبل أي تعديل يمسّ التخزين + `restoreUnifiedBackup` للاسترجاع.
- لا Migration بلا Backup مسبق (§18).

## تعريف الإنجاز النهائي (§73)
> التطبيق يعمل · البيانات محفوظة · CRUD يعمل · النماذج والنوافذ تعمل · الحسابات والعلاقات تعمل ·
> البحث والفلاتر والتقارير تعمل · الاستيراد/التصدير يعمل · Responsive وRTL والثيم تعمل ·
> الأداء محسّن · المعمارية أوضح · بلا Regression جوهري.
